# Kana-kanji conversion engine

`kana-kanji-converter` loads the Mozc five-column unigram, bigram, and trigram
dictionary shards generated by this repository. It builds a lattice over the
input reading and uses a cost-ordered beam search to select conversions. Phrase
entries compete directly with sequences of unigram entries, so observed two-
and three-word contexts can change the selected surface. Release directories
also contain `mozc-english-unigram-*` shards, which add English candidates for
katakana loanword readings stored as hiragana keys.

## Build and run

```console
cargo build --release --locked --manifest-path conversion-engine/Cargo.toml
conversion-engine/target/release/kana-kanji-converter \
  --dictionary path/to/extracted-dictionary \
  きょうはがっこうへいく
```

The dictionary argument can be an extracted release directory or an individual
`.txt`/`.txt.zst` shard. Repeat `--dictionary` to combine paths. To list several
candidates with their total costs:

```console
kana-kanji-converter -d path/to/dictionary -n 5 はし
```

For example, a release directory containing the JMdict-derived shard returns
`computer` among the candidates for either hiragana or katakana input:

```console
kana-kanji-converter -d path/to/dictionary -n 10 こんぴゅーた
kana-kanji-converter -d path/to/dictionary -n 10 コンピュータ
```

Omit the reading to convert standard input one line at a time without reloading
the dictionary:

```console
printf 'きょうははれ\nあしたもはれ\n' |
  kana-kanji-converter -d path/to/dictionary
```

Katakana and halfwidth katakana are normalized to hiragana. Characters not
covered by a dictionary entry are copied with a high fallback cost. Use
`--details` to inspect the chosen segmentation and whether each segment came
from a unigram, bigram, trigram, or fallback.

## Library

The crate also exposes `Dictionary`, `Converter`, `Candidate`, and `Segment`.
`Dictionary::load_dir` loads release shards, while `Converter::convert` returns
ranked candidates and their segment boundaries. The generated dictionary costs
already encode corpus frequency; no external Mozc runtime or connection matrix
is required by this engine.
